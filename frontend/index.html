INFRASTRUCTURE

Infrastructure components

Each layer is defined through reusable Terraform modules and independently configured by environment.

NET

Networking

Custom VPC spanning two Availability Zones with six subnets, Internet Gateway, NAT Gateways, route tables, and tier-specific security groups.

  • 2 public subnets
  • 2 private app subnets
  • 2 private DB subnets
  • 2 NAT Gateways
EC2

Compute

Amazon Linux EC2 instances are launched from a reusable launch template and managed through an Auto Scaling Group.

  • Application Load Balancer
  • EC2 Launch Template
  • Multi-AZ Auto Scaling
  • ALB health checks
DB

Database

MySQL runs inside dedicated private database subnets with encrypted storage and Multi-AZ high availability.

  • Amazon RDS MySQL
  • Multi-AZ deployment
  • Private networking
  • AWS-managed credentials
OBS

Monitoring

CloudWatch provides visibility into compute, load-balancer, and database health.

  • EC2 CPU alarms
  • ALB health monitoring
  • RDS CPU monitoring
  • Infrastructure dashboard

SECURITY

Security by architecture

Private Compute

Application EC2 instances run without public IP addresses inside private subnets.

Private Database

RDS is not publicly accessible and accepts MySQL traffic only from the application security group.

OIDC Authentication

GitHub Actions assumes an AWS IAM role through OIDC rather than storing long-lived AWS access keys.

Protected State

Terraform state is encrypted in S3 with versioning, public-access blocking, and state locking.
